# PROJECT MASTER SPECIFICATION
# THE WORLD OF TARUNYA
## An Immersive 3D Portfolio Experience for the Wispr Flow Hiring Challenge

You are acting as a senior creative developer, 3D web engineer, frontend architect, interaction designer, motion designer, and technical project lead.

Your job is to design and implement a highly polished, production-quality, immersive 3D portfolio website.

This is not a conventional developer portfolio. It must feel like an interactive digital world that visitors can explore, similar in spirit to an experimental game environment, cinematic 3D portfolio, and carefully art-directed digital experience.

The experience should take inspiration from the dreamlike architecture, immersive storytelling, and interaction philosophy of https://daikifujita.com/.

Study its visual and interaction patterns, including its distinction between conventional portfolio information and an alternative dream-like experience. Do not reproduce its exact assets, layout, branding, copy, or source code. Build an original experience with a comparable level of visual ambition.

5. 3D ENGINEERING STACK
==================================================

Use the following technologies as the primary stack.

Core:
- React 19, using compatible versions.
- TypeScript.
- Vite.
- Three.js.
- React Three Fiber.
- @react-three/drei.
- GSAP.
- GSAP ScrollTrigger.

3D rendering:
Use React Three Fiber as the React renderer for Three.js.

Use the Canvas component from @react-three/fiber as the persistent WebGL rendering surface.

Use Drei extensively where appropriate.

Useful Drei utilities:
- Environment.
- PerspectiveCamera.
- OrbitControls, only if a limited interactive camera mode is implemented.
- useGLTF.
- Html.
- Float.
- ContactShadows, if performance permits.
- Instances and Instances-related helpers.
- ScrollControls only if it is intentionally chosen as the scroll system.

Important:
Do not mix multiple competing scroll systems.

Preferred architecture:
A normal DOM scrolling container and GSAP ScrollTrigger should control the camera timeline.

Use one persistent Canvas component mounted for the entire experience.

Use a single world scene and a single primary camera.

Do not remount the Canvas for each district.

GSAP:
Use GSAP for:
- Camera movement.
- Camera rotation.
- Camera look-at target interpolation.
- District transitions.
- Scroll synchronization.
- Content reveal animations.
- Opening cinematic.
- Modal transitions.
- Section progress.
- Environmental animation timelines where useful.

Use ScrollTrigger with scrub-based animation for the main journey.

Use GSAP context and proper cleanup inside React effects.

Avoid creating duplicate timelines on re-renders.

Camera architecture:
Create a dedicated CameraRig component.

The drone camera should travel through a sequence of authored camera keyframes.

Each keyframe should include:
- Position.
- Target or look-at point.
- Optional camera roll.
- Field of view.
- Associated district.
- Scroll progress.

Interpolate smoothly between camera positions and target positions.

The camera should feel like a cinematic drone:
- Gentle acceleration.
- Smooth banking only when appropriate.
- Gradual altitude changes.
- Controlled perspective.
- No abrupt teleportation.
- No uncontrolled camera rotation.

Do not animate only camera position while leaving orientation unchanged. The camera's target must also move intentionally.

Use a stable, performant implementation for synchronizing GSAP with Three.js camera objects.

Canvas:
- One persistent Canvas.
- Appropriate antialiasing.
- Correct camera configuration.
- Controlled device pixel ratio.
- Appropriate color management.
- Responsive resizing.
- Suspense for asynchronous assets.
- Graceful error fallback.

Drei:
Use Drei for scene utilities, model loading, environment helpers, and interaction support.

11. PERFORMANCE AND ENGINEERING QUALITY
==================================================

The website must be visually impressive without becoming unusable.

Important performance requirements:

- Keep one Canvas mounted.
- Avoid unnecessary React state updates inside useFrame.
- Reuse geometries and materials.
- Use InstancedMesh for repeated vegetation and objects.
- Limit expensive real-time shadows.
- Use baked lighting where possible.
- Compress textures.
- Prefer optimized GLTF assets.
- Use lazy loading for large noncritical assets.
- Avoid unnecessary post-processing.
- Control device pixel ratio.
- Pause or reduce nonessential animations when the page is not visible.
- Clean up GSAP timelines and ScrollTriggers.
- Avoid duplicate event listeners.
- Avoid memory leaks from Three.js objects.
- Ensure the application can recover from loading errors.

Performance targets:
- Smooth interaction on a reasonably modern laptop.
- Aim for 60 FPS on capable desktop hardware.
- Avoid large initial asset downloads.
- Keep mobile experience lightweight.
- Monitor layout shifts and loading time.

Use browser performance tools and inspect console errors.

Do not claim a performance score without measuring it.
